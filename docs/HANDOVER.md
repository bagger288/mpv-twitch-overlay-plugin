## 1. Общее назначение и концепция проекта

**mpv-twitch-overlay-plugin** — это экосистема для воспроизведения, записи и архивирования стримов Twitch с интерактивным оверлеем чата в плеере **mpv**.

### Проблема, которую решает проект
1. **Утрата чата при просмотре записей (VOD)**: На Twitch записи часто удаляются, мьютятся из-за копирайта или разбиваются на куски при разрывах связи. Просмотр скачанного видеофайла в стандартном плеере лишает зрителя контекста чата.
2. **Тяжеловесность браузерных решений**: Браузерные оверлеи (Electron, Webview) потребляют гигабайты оперативной памяти и сотни мегабайт диска, вызывают рассинхрон при перемотке и не умеют работать оффлайн с локальными архивами.
3. **Фрагментированные записи (мультипарт)**: Если многочасовой стрим разбит на несколько видео (`part1.ts`, `part2.ts`, ...), стандартные инструменты не умеют поддерживать непрерывный таймлайн чата при переключении между файлами.

### Решение
- **Нативный C-плагин mpv на Rust (`twitch_chat.dll`)**: Рендерит растровый оверлей чата прямо поверх кадра видео с помощью низкоуровневой команды mpv `overlay-add`. Обеспечивает 60 FPS для анимированных эмоутов (GIF/WebP), нулевые накладные расходы браузерных движков, мгновенную перемотку, поиск по истории чата и ручную калибровку таймлайна.
- **Десктопный лаунчер (`twitch_launcher.exe`)**: Написан на Rust с UI-фреймворком **Slint 1.18**. Обеспечивает каталог записей, импорт чатов из архивов `bestlogs`, автоматическую загрузку кэша эмоутов (7TV, BTTV, FFZ, Twitch), прямую запись эфира через Streamlink с синхронным логированием IRC-сообщений, и фоновый агент мониторинга стримов (PC Agent) с интеграцией в системный трей Windows.

## 3. Модули плагина mpv (`twitch_chat_mpv`)

Плагин компилируется в динамическую библиотеку `twitch_chat.dll` (`cdylib`). Загружается mpv через ключ `--script=twitch_chat.dll`.

### 3.1. `src/lib.rs` (Ядро и цикл событий)
- **Точка входа**: `mpv_open_cplugin(handle: *mut mpv_handle) -> c_int`.
- **Подписка на события mpv**:
  - `time-pos` (флаг 1) — текущее время видео в секундах.
  - `path` (флаг 2) — путь к текущему воспроизводимому файлу из плейлиста.
  - `pause` (флаг 3) — состояние паузы плеера.
  - `vo-configured` (флаг 4) — готовность видеовывода к приему оверлеев.
  - `mouse-pos` (флаг 5) — координаты курсора мыши.
- **Ввод и биндинги**: Регистрирует input-секцию `define-section` через mpv API:
  - `script-binding <name>/twitch_chat_mouse` — перехват мыши (координаты, нажатия, отпускания, отмена).
  - `twitch_chat_search` — перехват клавиатурного ввода для строки поиска (латиница, кириллица, backspace, enter, esc).
- **Связка с `twitch_chat_input.lua`**: Companion Lua-скрипт используется для надежного текстового ввода в поисковую строку на платформах, где прямой C-перехват клавиш ограничен.
- **Вывод оверлея (`overlay_add_bgra`)**: Генерирует массив пикселей BGRA, сохраняет во временный файл `%TEMP%\mpv_twitch_overlay_1.raw` и выполняет команду mpv `overlay-add 1 <x> <y> <file> 0 "bgra" <w> <h> <stride>`. Это полностью устраняет задержки межпроцессного IPC при передаче десятков мегабайт графики в секунду.

### 3.2. `src/renderer.rs` (Двухслойный рендеринг)
Для достижения плавной анимации 60 FPS без перерисовки сотен текстовых строк реализована **двухслойная схема**:
1. **Базовый слой (`ChatScene`)**:
   - Формируется в `prepare_chat_scene()` только при смене видимых сообщений или ресайзе панели.
   - Рендерит фон, границы, ники, бейджи и статический текст в один растр через `tiny-skia`.
   - Токены анимированных эмоутов (GIF/WebP) исключаются из статического слоя, а их координаты и размеры сохраняются в структуру `AnimatedImage`.
2. **Анимационный слой (`render_scene`)**:
   - Вызывается по таймеру `animation_due` (шаг до 16.67 мс).
   - Сэмплирует текущий кадр каждого анимированного эмоута из `EmoteCache`.
   - Если ни один кадр анимации не изменился с прошлого прогона, возвращается `pixels: None` — mpv `overlay-add` не вызывается, экономя ресурсы GPU/CPU.
3. **Режимы отображения**:
   - Вкладка **Чат** (просмотр текущего потока сообщений, привязанного к видео).
   - Вкладка **Поиск** (поиск сообщений по тексту или нику с подсветкой и возможностью перемотки).
   - Вкладка **Настройки** (размер шрифта, прозрачность, обводка/тень, переключатели бейджей/эмоутов).
   - **Свернутое состояние (Minimize)**: Клик по крестику шапки сворачивает оверлей в компактную плашку 44×44 px с логотипом Twitch. Плашка свободно перетаскивается мышью в любую точку экрана; клик разворачивает чат обратно.
   - **HeaderFade**: Автоматическое плавное скрытие шапки окна при отсутствии активности курсора (~180 мс появление, ~220 мс затухание).

### 3.3. `src/layout.rs` (Верстка текста и шрифты)
- Реализует правила типографики живого веб-интерфейса Twitch:
  - Размер шрифта по умолчанию: 14 px.
  - Высота строки (line-height): 22 px.
  - Размер эмоута: контейнер 28 px по высоте.
  - Размер бейджей: 18 px с нижним отступом 1.5 px.
- **Шрифтовая подсистема (`fontdue`)**:
  - В бинарник встроены 4 шрифта: `DejaVuSans.ttf`, `twitch-inter-latin-400.ttf`, `twitch-inter-latin-700.ttf`, `twitch-inter-cyrillic-400/700.ttf`.
  - Кириллица (U+0400–U+052F) и символ `№` направляются в Inter Cyrillic.
  - Если глиф отсутствует в основном шрифте, срабатывает fallback на DejaVu Sans.
  - Кернинг извлечен из GPOS-таблиц и сконвертирован в старый формат `kern` скриптами подготовки шрифтов, так как `fontdue` не читает сложные таблицы GPOS напрямую.

### 3.4. `src/emotes.rs` и `src/animation.rs` (Кэш и анимации)
- **Многопоточное декодирование**: Фоновый рабочий поток декодирует изображения по mpsc-каналу, исключая микрофризы плеера при подгрузке новых эмоутов.
- **LRU-кэш**: Ограничен объемом 96 МБ. Дубликаты одного и того же эмоута разделяют общий `Arc<Pixmap>`.
- **Поддержка форматов**:
  - WebP (через `image::codecs::webp::WebPDecoder`).
  - GIF (через `image::codecs::gif::GifDecoder`).
  - PNG/JPEG (статические превью и бейджи).
- **Лимиты безопасности**: Размер файла до 16 МБ, не более 600 кадров, не более 64 Мп в сумме. Если анимация повреждена или превышает лимиты, происходит автоматический откат на статическое PNG-превью.

### 3.5. `src/session.rs` (Мультипарт и сессии)
- Управляет загрузкой `.session.json`.
- **Мультипарт**: Рассчитывает абсолютное смещение времени для каждого фрагмента видео (`PartInfo { file, start_ms, end_ms }`).
  - Метод `part_index(path)` сопоставляет путь текущего файла в mpv с частями сессии.
  - Метод `visible_messages(current_ms, ui, max)` выбирает сообщения, попадающие в текущее окно просмотра.
- **Калибровка (`calibrate_anchor`)**: Если чат спешит или отстает от видео, пользователь может откалибровать точку синхронизации прямо в UI. Смещение сохраняется атомарно во все части сессии.
- **Поиск**: Функция `search_for_video` ищет совпадения по тексту и никам. При клике на результат поиска плагин не только перематывает видео, но и при необходимости переключает текущий файл в плейлисте mpv (`loadfile` / `playlist-play-index`).

## 4. Модули лаунчера (`twitch_launcher` на Slint 1.18)

Лаунчер написан на Rust с использованием Slint 1.18. При запуске без аргументов открывается графическое окно. При запуске с аргументом `render-chat` запускается консольный режим рендера видео.

### 4.1. `launcher-slint/src/main.rs` (Контроллер и жизненный цикл)
- Инициализирует окно `MainWindow::new()`.
- Применяет темную тему заголовка Windows через `win_dark_mode::apply_dark_titlebar()` (Win32 API `DwmSetWindowAttribute`).
- Запоминает и восстанавливает размер и координаты окна в `config.json`.
- Создает компонент `LauncherTray` (системный трей Windows через Slint `SystemTrayIcon`).
- Перехватывает событие закрытия окна `window.on_close_requested`:
  - Если запись не идет, сохраняет геометрию и показывает модальный диалог: **"Свернуть в трей"** или **"Выйти"**.
- Организует потокобезопасную передачу данных в UI через `slint::invoke_from_event_loop`.

### 4.2. `launcher-slint/ui/main.slint` (Пользовательский интерфейс)
Окно лаунчера имеет базовый размер 680×780 px (минимальный 560×640 px) в фирменной темной палитре Twitch (`c_bg: #18181b`, `c_accent: #9146ff`, `c_card: #1f1f23`).

Вкладки:
1. **0: «Записи»**:
   - Выпадающий список/селектор каналов (стримеров).
   - Таблица сессий стримера: дата, количество частей, длительность, размер на диске, наличие чата (✓) и эмоутов (✓).
   - Кнопки: «Папка сессии», «▶ Смотреть в mpv» (двойной клик по строке также запускает просмотр).
2. **1: «Импорт»**:
   - Поле ввода канала Twitch.
   - **Менеджер частей видео**:
     - Кнопка «+ Добавить видео…» (диалог выбора нескольких файлов: `.ts`, `.mp4`, `.mkv`).
     - Автоматическая естественная сортировка (`natural_sort_key`) при добавлении.
     - Список частей: номер, имя файла, размер, кнопки вверх (`▲`), вниз (`▼`), удалить (`x`).
     - Авто-растяжение высоты списка: от 1 строки (32 px) до 5 строк (168 px), далее включается плавный скроллинг `ScrollView`.
     - Фиксированный размер кнопок управления (`horizontal-stretch: 0`) с распоркой `Rectangle { horizontal-stretch: 1; }`.
     - Кнопка «Очистить».
   - Поле времени старта (UTC) с опцией автоопределения по активности чата.
   - Прогресс-бар и лог импорта.
3. **2: «Запись» (Live Recorder)**:
   - Ручной запуск записи трансляции канала по имени.
   - Выбор качества видео (`best`, `1080p60`, `720p60`, `audio_only` и т.д.).
   - Консоль вывода логов Streamlink и процесса захвата IRC.
   - Индикаторы реального времени: статус, время записи, размер видеофайла, счетчик полученных сообщений чата.
4. **3: «PC Agent»**:
   - Фоновый агент мониторинга активности стримеров.
   - Подключается к серверу координации или мониторит локальный список каналов.
   - Автоматически стартует запись при выходе стримера в онлайн.
   - Индикация текущего статуса, логов, длительности текущей сессии.
5. **4: «Настройки»**:
   - Пути к системным утилитам: `streamlink`, `mpv`, `ffmpeg`. Валидация подсвечивает статус (найден/зеленый или ошибка/красный).
   - Настройки Twitch API: Client ID, App Token, Client Secret, Refresh Token (поля секретов маскируются звездочками, есть кнопка ручного обновления токена).
   - Папка для сохранения записей (`records`).
   - URL сервера мониторинга для PC Agent и URL прокси-плейлиста стримов.
   - Выбор движка оверлея (`Auto`, `Rust DLL`, `Lua`).

### 4.3. `launcher-slint/src/records.rs` (Сканирование записей)
- Сканирует подкаталоги в папке `records/`.
- Принимает папки вида `<channel>_<DD-MM-YYYY_HH-MM-SS>`.
- Считывает `<folder>.session.json` и проверяет наличие видеофайлов и чата.
- Функция `detect_channel_and_date(path: &Path)`: Интеллектуальный парсер имен файлов при ручном импорте. Умеет извлекать имя канала и дату из типовых шаблонов (например, `streamer_2026-11-15.mp4` или `2026-11-15_streamer.ts`).

### 4.4. `launcher-slint/src/importer.rs` (Импорт логов)
- Загружает логи чата из сервиса `bestlogs.lurkology.com` за указанные даты.
- Нормализует временные метки IRC в единый стандарт UTC.
- Запускает `ffprobe` для измерения точной продолжительности каждого видеофайла из списка частей.
- Формирует итоговый `*.session.json` с массивом `parts`, где для каждого видео прописаны `start_ms` и `end_ms`.
- Запускает кэширование эмоутов через `emotes.rs`.

### 4.5. `launcher-slint/src/chat_logger.rs` (Захват чата в реальном времени)
- Асинхронный клиент Tokio, подключающийся по TLS к `irc.chat.twitch.tv:6697`.
- Запрашивает Twitch IRC capabilities: `twitch.tv/tags`, `twitch.tv/commands`.
- Сохраняет каждое входящее сообщение `PRIVMSG`, `USERNOTICE` в файл `<session>.chat.jsonl` в формате:
  ```json
  {"timestamp": 1731650000123, "raw": "@badge-info=... :user!user@user.tmi.twitch.tv PRIVMSG #channel :text"}
  ```
- Использует точную серверную метку времени `tmi-sent-ts` из тегов Twitch IRC для исключения рассинхрона из-за сетевых задержек.

### 4.6. `launcher-slint/src/recorder.rs` (Процесс записи)
- Управляет жизненным циклом процесса Streamlink:
  `streamlink twitch.tv/<channel> <quality> -o <session_dir>/video.ts ...`
- Параллельно запускает `chat_logger`.
- Контролирует обрывы связи и перезапускает захват при кратковременном падении стрима.
- По завершении записи формирует валидный `SessionManifest` и запускает фоновый сбор эмоутов.

### 4.7. `launcher-slint/src/agent.rs` (PC Agent и безопасность диска)
- Фоновый монитор стримов.
- **Контроль дискового пространства**:
  - Перед запуском и во время записи опрашивает Win32 API `GetDiskFreeSpaceExW`.
  - При свободном месте менее 3.0 ГБ выдает предупреждение.
  - При свободном месте менее 150 МБ аварийно останавливает запись во избежание повреждения файловой системы.
- **Уведомления Windows**:
  - Отправляет нативные тосты через WinRT (`Windows.UI.Notifications.ToastNotificationManager`) и звуковой сигнал `MessageBeep`.

### 4.8. `launcher-slint/src/render_chat.rs` (Рендер чата в видео)
- Вызывается при запуске лаунчера с флагом `render-chat`:
  `twitch_launcher.exe render-chat --session <path> --video <name> --start <sec> --duration <sec> --output <path> --fps <fps>`
- Позволяет запечь чат в отдельный видеофайл с прозрачным фоном или наложить его на видео через конвейер `ffmpeg` без запуска графического интерфейса.

## 5. Структура данных и форматы файлов

Все данные стрима хранятся внутри изолированного каталога сессии в `records/`:

```
records/
└── streamer_15-11-2026_18-30-00/
    ├── streamer_15-11-2026_18-30-00.session.json   # Главный манифест сессии
    ├── streamer_15-11-2026_18-30-00.chat.jsonl     # Лог сообщений чата
    ├── chat_settings.json                          # Настройки оверлея конкретно для этой записи
    ├── video.ts (или video_part1.ts, video_part2.ts) # Видеозаписи стрима
    └── emote_cache/                                # Локальный кэш картинок
        ├── manifest.json                           # Карта слов, бейджей и эмоутов
        ├── 7tv/                                    # Эмоуты 7TV (.webp, .png, .gif)
        ├── bttv/                                   # Эмоуты BetterTTV
        ├── ffz/                                    # Эмоуты FrankerFaceZ
        └── twitch/                                 # Нативные эмоуты и бейджи Twitch
```

### 5.1. Манифест сессии (`*.session.json`)
```json
{

  "room_id": "12345678",
  "session_start_ms": 1731688200000,
  "parts": [
    {
      "file": "E:/records/streamer_15-11-2026_18-30-00/video_part1.ts",

    },
    {

```
*Примечание*: Сериализатор Rust использует `#[serde(flatten)] extra` — любые дополнительные поля, добавленные сторонними скриптами, сохраняются без потерь при перезаписи файла.

## 6. Жизненный цикл сессий и сценарии работы

### Сценарий А: Воспроизведение записи
1. Пользователь выбирает канал и сессию во вкладке «Записи» лаунчера.
2. Лаунчер вызывает модуль `player.rs`:
   - Формирует список видеофайлов из `parts`.
   - Запускает `mpv.exe` с аргументами:
     `--script=build/twitch_chat.dll`
     `--script-opts=twitch_session="<full_path>/<session>.session.json"`
     `--script="<project_root>/twitch_chat_input.lua"`
     `video_part1.ts video_part2.ts ...`
3. Плагин `twitch_chat.dll`:
   - Инициализируется в `mpv_open_cplugin`.
   - Загружает манифест сессии, строит индекс сообщений чата из `.chat.jsonl` в памяти.
   - Инициализирует `EmoteCache` с предзагрузкой `manifest.json`.
   - При воспроизведении читает свойство mpv `time-pos`, преобразует его в абсолютные миллисекунды стрима с учетом текущей части плейлиста.
   - Отбирает сообщения, рендерит BGRA-буфер и передает в mpv через `overlay-add`.

### Сценарий Б: Импорт внешних записей
1. Пользователь скачал стрим из сети, разделенный на части: `part1.ts`, `part2.ts`.
2. Открывает вкладку «Импорт».
3. Нажимает «+ Добавить видео…» и выбирает оба файла.
4. Лаунчер автоматически запускает естественную сортировку (`natural_sort_key`), гарантируя порядок `part1` -> `part2` независимо от порядка выбора в проводнике.
5. Лаунчер автоматически определяет имя стримера и дату из имени файла.
6. Пользователь нажимает «Импортировать».
7. `importer.rs` скачивает логи с `bestlogs`, вычисляет длительности видео через `ffprobe`, связывает части таймлайна и сохраняет готовую сессию в `records/`.
8. По завершении импорта список видеофайлов автоматически очищается.

## 7. Подводные камни, баги и специфика окружения

### 7.1. Ограничение цикла событий Winit в Slint
- **Проблема**: В тестах Rust вызов `MainWindow::new()` более одного раза за один запуск тестового процесса вызывает панику `EventLoop can't be recreated`. Это фундаментальное архитектурное ограничение библиотеки `winit` на Windows.
- **Решение**: Все тесты свойств и моделей лаунчера, требующие инициализации `MainWindow`, объединены в **один** модульный тест (`test_launcher_window_properties` в `launcher-slint/src/main.rs`). Новые UI-проверки следует добавлять в этот существующий тест, а не создавать новые тесты с отдельным `MainWindow::new()`.

### 7.2. Потокобезопасность моделей Slint (`Rc<VecModel>` и `Send`)
- **Проблема**: `Rc<VecModel<T>>` не реализует трейт `Send`. Попытка передать `Rc<VecModel>` напрямую в фоновый поток `std::thread::spawn` или `tokio::spawn` приводит к ошибке компиляции `E0277`.
- **Решение**: Фоновые потоки должны манипулировать стандартными типами данных Rust (`Vec<T>`, защищенный `Arc<Mutex<Vec<T>>>>`). Обновление UI выполняется через `slint::invoke_from_event_loop`:
  ```rust
  let handle_weak = handle.clone();
  slint::invoke_from_event_loop(move || {
      if let Some(ui) = handle_weak.upgrade() {
          let new_model = Rc::new(VecModel::<Item>::default());
          // заполнение new_model
          ui.set_property(ModelRc::from(new_model));
      }
  });
  ```

### 7.3. Ложные срабатывания Windows Defender (False Positive Heuristics)
- **Проблема**: Свежесобранный `twitch_launcher.exe` без цифровой подписи (EV Code Signing) может детектироваться антивирусом Windows Defender (эвристические детекты `Wacatac`, `Trojan:Win32/ML` и т.п.).
- **Причина**: Лаунчер содержит код для запуска дочерних процессов (`powershell` для тостов, `streamlink`, `mpv`), использует прямые вызовы Win32 API (`GetDiskFreeSpaceExW`, `MessageBeep`, `DwmSetWindowAttribute`), работает с сетью (IRC/TLS) и скомпилирован компилятором Rust со стриппингом отладочных символов (`strip = true`).
- **Решение**: Добавить рабочую папку репозитория и `target/` в исключения Windows Defender на машине разработчика. Для релизных сборок использовать подпись сертификатом.

### 7.4. Поведение кнопок в `HorizontalLayout` Slint
- **Проблема**: В Slint стандартный `Button` без явного `horizontal-stretch: 0` растягивается вместе с разделителем `Rectangle { }`. Если кнопки монтируются динамически по условию (`if`), оставшееся пространство перераспределяется, заставляя соседние кнопки непредсказуемо менять ширину.
- **Решение**: Всем кнопкам в строках управления обязательно задавать `horizontal-stretch: 0;`, а распорке между текстом и кнопками — явный `Rectangle { horizontal-stretch: 1; }`.

### 7.5. Отображение специальных глифов Unicode
- **Проблема**: Символ умножения/крестика `✕` (U+2715) на некоторых сборках Windows в шрифтах Slint отображается как пустой квадрат (символ отсутствия глифа `.notdef`).
- **Решение**: Использовать стандартный ASCII-символ `x` с красным цветом подсветки или встроенный SVG/Image ресурс.

### 7.6. Предупреждения компилятора Rust 2024 (`static_mut_refs`)
- **Проблема**: В `src/mpv_api.rs` присутствуют 11 предупреждений компилятора о взятии ссылки на `static mut VTABLE`.
- **Решение**: Таблица указателей функций mpv `VTABLE` заполняется один раз при вызове `mpv_open_cplugin`. Это классический паттерн для плагинов mpv на C/Rust. Не изменять без необходимости переписывания на `AtomicPtr` или `OnceCell`.

1. **Проверьте ветку Git**: Основная разработка ведется в ветке `main`.
